## Assessment

The current animations are useful execution diagrams. Lanes and explicit
events make them suitable for the detailed runtime guides. Across ten
animations, however, repeated layouts and equal visual weight make the README
feel like a manual. At normal README width, 11.5–12.5px source labels shrink
further, while full sentences compete with the moving event chips. A late
arrival also needs to wait through a cycle to reconstruct the story.

The redesign changes the composition rather than adding more effects:

- One opening diagram makes the controller/turn separation tangible.
- Quickstart follows the opening, before the detailed architectural tour.
- Customization follows quickstart, with coding-agent skills and application
  patterns close to the first successful run.
- Two further diagrams explain recovery and background conversation compaction.
- A compact task-oriented feature table links to the deeper guides.
- The full sequence diagram and per-feature timelines remain available as
  detailed reference material; they need not all occupy the landing page.

## Motion system

Three beats: establish the state, change one thing, show the consequence.
Keep the spatial arrangement and main labels visible throughout. Animate only
the current signal, progress, status, or compaction—not the entire diagram.
Hold the final state long enough to read it. Avoid bounce, glow, decorative
gradients, and accumulating labels.

Purple identifies active control/context, green identifies acknowledged or
recorded work, and neutrals carry stable structure. Meaning is also expressed
through text and check marks. Each animation includes a title and description,
light/dark palettes, and a reduced-motion final state.

Desktop assets are 800px wide, with 18–20px primary labels. Separate 380px mobile
compositions rearrange the diagram vertically instead of shrinking its text.
The README uses native `<picture>` elements to select the composition.

## Assets

Generated by `.misc/animations/landing.py`:

- `docs/images/landing-control.svg` and `landing-control-mobile.svg`
- `docs/images/landing-recovery.svg` and `landing-recovery-mobile.svg`
- `docs/images/landing-context.svg` and `landing-context-mobile.svg`

Each composition also has a `-still.svg` final-state asset. Explicit reduced-motion
`<source>` entries select these even when a browser does not forward that media
preference into an embedded SVG document.

Regenerate all twelve assets from the repository root:

```sh
python3 .misc/animations/landing.py
```

The assets use CSS animation inside self-contained SVGs: no scripts, external
fonts, image fetches, or runtime dependencies. The existing frame renderer
can inspect their 15-second cycles at 1.5, 7, and 12.5 seconds.

## Behavioral boundaries

- Steering preserves running tools; the next model step consumes the input.
- Recovery reuses recorded results; it does not promise exactly-once external
  effects when a crash precedes journaling.
- The compaction animation illustrates background conversation summarization.
  The page separately identifies blocking in-turn context compaction.
