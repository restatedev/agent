# README animations

The animated SVGs in `docs/images/` are generated by the scripts in this
directory. Do not edit the SVGs by hand: their keyframes are computed, so edit
the generator and regenerate.

This file is written for whoever changes them next, human or Claude. Read it
fully before touching an animation.

Code paths are relative to `packages/libs/core/src`. `docs/images/layers.svg`
is a static diagram written by hand, not generated.

**Accuracy rule.** Every animation makes claims about runtime behaviour. When
the code in the last column changes (a threshold, a handler becoming shared or
exclusive, how steering is consumed), update the animation and its README
caption in the same change. Before adding a claim, find it in the code.

## Regenerate

From the repository root:

```sh
python3 .misc/animations/hero.py                    # docs/images/durable-turn.svg
python3 .misc/animations/timeline.py                # every timeline animation
python3 .misc/animations/timeline.py docs/images steering compaction   # only some
```

Python 3 standard library only. Output is deterministic: regenerating
without changing a script must leave `git status` clean. Check that after any
refactor of the helpers.

## Check what you made

You cannot see an animation by reading the SVG. Render frames and look at
them, in both themes, at several points in the loop:

```sh
python3 .misc/animations/render_frames.py docs/images/steering.svg /tmp/frames 3 6.5 14.5
```

The arguments after the output directory are seconds into the loop. The
script writes `<name>-light-<t>.png` and `<name>-dark-<t>.png` using headless
Chrome (set `CHROME=/path/to/chrome` if it is not in the macOS default
location). Pick times that show each caption phase, plus the last frame
(about 14.5s of a 16s loop, when everything is visible). To catch a moving
element (a packet, the replay cursor), convert its percentage to seconds:
`t = percent / 100 * loop_seconds`.

Look for: overlapping chips, labels running into bars, anything past the
right edge of a lane (x ≈ 984), and captions longer than the width.

For the README's mermaid sequence diagram:

```sh
awk '/```mermaid/{f=1;next}/```/{f=0}f' README.md > /tmp/seq.mmd
npx -y @mermaid-js/mermaid-cli@11 -i /tmp/seq.mmd -o /tmp/seq.png -w 1200
```

## How the animations work

They are plain SVG with an inline `<style>`: CSS `@keyframes`, no JavaScript,
no external fonts or images. GitHub renders README images with `<img>`, which
allows CSS animation but no scripts or external resources, so keep it that way.

- **One clock.** Every animated element loops over the same duration
  (`seconds`, usually 16) with `linear infinite`, and its keyframes are in
  percent of that loop. Elements appear at their percentage, stay until
  `HOLD_END` (93%) and fade out before the loop restarts.
- **Static frame = finished state.** The base CSS shows the final frame, and
  `prefers-reduced-motion` turns animation off, so a static render shows the
  whole story with the last caption. Elements that must be hidden in the final
  frame (earlier captions, transient states) are listed in `Animation.hidden`,
  which `visible_between` fills in for you.
- **Themes.** Colours are CSS custom properties on `:root`, redefined under
  `@media (prefers-color-scheme: dark)`. Use the tokens (`--ok`, `--bad`,
  `--warn`, `--model`, `--tool`, `--accent`, …), never literal colours, or
  dark mode breaks.
- **Timeline animations** (`timeline.py`) have lanes and a playhead that
  sweeps from `x0` to `x1` between 0% and `playhead_end`. `a.x(p)` maps a
  percentage to the playhead's x position, so an event placed at `p` appears
  exactly when the playhead reaches it. With the defaults (x0 = 170,
  x1 = 975, playhead_end = 86) one percent is about 9.4px: a 120px chip
  occupies about 13% of the timeline. Use that to space chips in one lane.
- **Growing bars** use `transform: scaleX` with `transform-box: fill-box`
  and `transform-origin: 0 50%`. Animating `width` is not reliable across
  browsers. Dashed bars look squashed while they grow; that is accepted.

## The `timeline.py` helpers

```python
a = Animation(width, height, seconds, playhead_end)
a.lane(y, h, "Label", "sub-label")                   # background band
a.chip(p, y, width, kind, "title", "subtitle")      # event box, left edge at x(p)
a.bar(p_start, p_end, y, kind, "label", label_on_bar=False, height=14)
a.mark(p, y, kind, "✓")                             # small symbol
a.axis_label(p, y, "text")                          # muted small text
a.time_break(p, y0, y1, "")                         # zig-zag: compressed time
a.playhead(y0, y1)
a.captions(y, [("text", start, end), ...])          # one caption per phase; last end = 101
a.write("file.svg", "aria-label describing the whole animation")
```

Chip kinds: `user`, `model`, `tool`, `reply`, `ok`, `bad`, `warn`, `code`.
Bar kinds: `tool`, `ok`, `bad`, `wait` (dashed, warn colour), `idle` (dashed,
muted). Mark kinds: `ok`, `bad`, `accent`.

For layouts that are not a timeline (`compaction`, `in-process`) the same
object is used without a playhead: append raw SVG to `a.body`, create a
unique class with `a.fresh("e")`, and give it keyframes with `a.appear_at`,
`a.visible_between` or `a.keyframes`. Extra CSS goes in `a.css`.

## Editing an animation

1. Change the generator function (labels, percentages, widths).
2. Regenerate only that one: `python3 .misc/animations/timeline.py docs/images <name>`.
3. Render frames in both themes and look at them.
4. If the story changed, update the README caption next to the image and
   its alt text (the `![...]` text), and the `aria-label` in `a.write`.

Keep captions to one line at 15px (about 95 characters for a 1000px-wide
SVG). Keep each chip's text within its width: bold 12.5px is about 7px per
character.

## Adding an animation

1. Confirm the behaviour in the code and note where it lives.
2. Write a generator function in `timeline.py`, copying the closest existing
   one, and register it in `ANIMATIONS` at the bottom.
3. Use three caption phases: the setup, the interesting moment, the payoff.
4. Generate, render at each phase and the final frame, fix overlaps.
5. Add it to the README next to the text it explains, with alt text
   describing the whole sequence, and add a row to the table above.

Put an animation where it breaks up a long stretch of text and illustrates
exactly that text. Do not stack animations with nothing between them.

## Environment gotchas

- The sandboxed shell may use GNU `sed`: write `sed -i -e …`, not the
  macOS `sed -i '' -e …`.
- Headless Chrome follows the OS theme. `render_frames.py` forces each scheme
  with `--blink-settings=preferredColorScheme=0|1`.
- In a worktree-isolated Claude session, commands that compute paths in shell
  variables can be refused. Spell paths out literally.
